# 模型设置与调用故障

桌面端的模型地址、模型名称和 API Key 必须属于同一套服务。Base URL 是兼容 OpenAI Chat Completions 的接口根地址，模型名称应填写服务商提供的实际模型 ID。

## 保存与凭据归属

- `desktop` 档允许自定义地址；`prod` 档保留管理员控制的地址限制。设置页面按 `customBaseUrlAllowed` 显示可编辑状态。
- 禁止的地址、无效 URL、未知预设和超过数据库字段长度的配置，会整组拒绝；不会只保存模型名称和 Key。
- 不同于预设的自定义地址必须明确填写模型名称和用户自己的 Key，不能继承平台 Key。
- 用户 Key 会与实际 Base URL 一同绑定保存。切换预设、修改地址，或管理员更改同名预设的地址，都不能把旧 Key 自动带到新端点。
- Key 留空只允许保留已绑定当前端点的 Key。输入新 Key 会重新绑定；明确勾选清除会同时清除 Key 和绑定地址。
- 保存和恢复默认共用一个进行中状态，阻止同一页面并发写入造成响应乱序。
- Key 按加密后的实际长度校验，统一支持最多1024字符密文；超限返回 `API_KEY_TOO_LONG`，整组配置不落库。V27迁移扩展旧桌面端的512字符列，保留更大的历史列。

历史版本没有记录 Key 的绑定地址，无法可靠重建其归属。V26 迁移只添加绑定字段，保留历史密钥，不猜测地址、不自动回填。升级后存在未绑定 Key 的用户需要重新输入服务地址、模型名称和对应 Key；也可以清除旧 Key 后使用预设。无效配置仍可打开设置页面修复，不会把回退地址伪装成“当前生效”。

## 模型上下文窗口

设置页可填写服务商声明的输入上下文窗口（token）。`PUT /api/model` 的可选 `contextWindowTokens` 接受0（自动）或1024至10000000的整数；旧客户端不传该字段时，仅在实际端点和模型都未变化时保留原值。`GET /api/model` 返回用户填写值、生效预算、来源及提示。

- 与所选预设端点、模型一致时，自动采用预设窗口；用户填写正数可降低预算，不能突破已知预设上限。
- 自定义端点或模型的容量不能从原预设继承。未填写时使用8192 token保守预算，并明确提示“窗口未确认”；这不是自动识别出的模型容量，也不保证适用于所有服务商。应按实际服务商的输入上限填写。
- 模型连接可以缓存，但每次解析必须返回当前用户的窗口和预设信息。默认窗口也受显式输入硬上限约束。
- 如果窗口连本轮工具定义和最低消息预算都无法容纳，执行器会在模型请求前停止并提示核对窗口，不会通过抬高预算越过已知上限。

V27新增可空的用户窗口字段，不根据模型名称猜测或回填历史容量。

## 任务启动时的模型错误

任务策略路由保留以下原因，并生成不含上游原始响应、请求正文或密钥的可操作提示：

| 原因 | 提示与处理 |
| --- | --- |
| `ROUTER_MODEL_AUTHENTICATION_FAILED` | 401：核对地址、模型和该服务商的 Key |
| `ROUTER_MODEL_PERMISSION_DENIED` | 403：检查账号与模型权限 |
| `ROUTER_MODEL_NOT_FOUND` | 404：检查 Base URL 和模型 ID |
| `ROUTER_MODEL_RATE_LIMITED` | 429：检查额度或稍后重试 |
| `ROUTER_MODEL_TIMEOUT` | 检查服务响应、网络与代理 |
| `ROUTER_MODEL_CONNECTION_FAILED` | 检查地址、DNS、网络与代理 |
| `ROUTER_MODEL_SERVICE_UNAVAILABLE` | 5xx：稍后重试或切换服务 |
| `ROUTER_MODEL_INVALID_REQUEST` | 检查接口与 Chat Completions 的兼容性 |

模型不可用、调用失败或路由响应未通过校验时，本轮任务失败，不调度节点，也不回退到平台凭据。失败原因通过任务状态与 SSE 传给客户端；原有任务进度不被覆盖。

后台画像与记忆巩固同样遵守用户模型配置。已知用户的配置解析失败或会话归属查询失败时，停止该次后台处理，不把用户对话发往全局模型；未处理的记忆事件保留以待配置修复后重试。绑定失败也必须恢复线程原有的用户、项目和模型上下文。

## 验证方式

`UserModelConfigConsistencyTest` 与 `UserModelConfigSecretTest` 验证整体保存、凭据绑定和脱敏；`ModelCredentialEndpointMigrationTest` 验证旧库迁移。`ModelConfigurationRoutingIntegrationTest` 使用本地 HTTP 服务和假 Key，验证保存后的地址、Authorization 与模型 ID 实际进入请求，以及上游 401 时没有工具执行或平台请求。它不验证真实服务商账号或密钥是否有效。
