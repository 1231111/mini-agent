# 本地记忆检索的内容向量缓存

`LocalHybridSearchEngine` 继续对完整、已授权的候选集评分，不通过截掉候选来降低耗时。空候选（包括类型或重要度筛选后的空集）立即返回，不初始化或调用 embedding。

查询向量每次请求计算一次；记忆内容向量在同一进程内复用。缓存键包含租户、作用域类型、作用域 ID、内容 SHA-256、模型实例身份、模型配置与版本、查询向量维度。内容更新会使用新的键；同样文本在不同归属下独立缓存。缓存只保留摘要键和向量，不把原始记忆文本或查询文本作为缓存键保存，也不包含 API Key。

```yaml
agent:
  memory:
    vector:
      cache:
        max-entries: 2048
        max-bytes: 33554432 # 32 MiB，仅向量负载；键/条目元数据另受条数限制
        ttl-seconds: 1800  # 写入后固定 TTL；命中不延长
        max-in-flight: 32 # 在途计算去重表上限；达到上限后可中断地等待
        model-revision: "1"
```

LRU 同时限制条数和向量负载字节数。过期向量不能命中，闲置过期项在后续访问时清理。多个并发请求对同一键只计算一次；不同键最多占用配置数量的在途槽位。失败、空向量、全零、非有限值或维度不匹配的结果不缓存；后续请求可以重新计算。返回数组与内部缓存隔离，调用方不能改坏缓存。

模型命名空间包含 provider、endpoint、model 名和显式 `model-revision`。本地 ONNX、伴生 `.data` 和 tokenizer 文件还记录路径、文件大小及修改时间。更换模型配置或模型实例不复用旧命名空间。**远端服务在相同 endpoint/model 名下替换权重时，必须提升 `model-revision` 并重启后端；文件替换也需重启，确保实际运行的模型已重新加载。** 客户端无法从相同模型名自动识别服务端无通知的权重变化。

边界：缓存是易失的，重启、TTL 到期或容量淘汰后需要再次计算；冷查询仍计算每个未命中的候选向量。候选数据库读取、关键词评分和最终排序仍遍历完整候选，尚未实现持久向量索引。因此这次消除了热查询的重复模型推理，不等于解决超大记忆库的全部检索开销。

`agent.memory.vector.enabled` 不是共享 embedding 的总开关；结构化本地检索是否计算向量仍取决于 `SharedEmbeddingModel.isEnabled()`。本次没有改变全局 embedding 的行为。
